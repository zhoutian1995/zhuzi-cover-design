# 验收与使用示例

## 交付检查

| 检查 | 通过标准 |
|---|---|
| 受众匹配 | 按用户当前稿件、账号定位与素材选择本题读者；标题让目标读者知道在解决什么 |
| 内容可信 | 封面承诺能够在正文找到依据；没有挪用别人的数字成绩 |
| 经历与结果支持 | 履历、阅读量和第一人称经历符合正式档案；不把前雇主任职包装成AI资历，不虚构收入或转型效果；真实代码、报错、diff与结果来自本次材料，概念图明确是示意 |
| 三个视觉锚点 | 第一眼能找到钩子词、人物或主道具、内容证据 |
| 网格可读 | 在约 180×240 的 3:4 预览中能读出主题与重点词，辅助字可忽略 |
| 本人身份与系列外观 | 有用户已确认的本人系列人像时，以其外观、脸部精修与用光为视觉基线，原片／新脸模辅助真人身份，不自动重塑骨相、表情和摄影气质。用户明确要新外观或没有已确认基线时，用最新真人参考建立外观；生成图不循环冒充独立身份证据 |
| 自然上镜精修 | 在保留真实脸型、骨相、眼型与鼻口的前提下，均匀肤色，柔化眼下、粗重胡须阴影与疲态，用柔光保留立体感和眼神亮点，整理真实短发。身份保真与自然上镜须同时通过；不能为保真故意加重疲态和瑕疵，也不能美化成陌生人 |
| 人物衔接 | 比较脸与肩胸的相对宽度、厚度、脖子透视、躯干与衣服体积，检查脸颈肩躯干一体关系；头部画面占高不能替代头身协调，不固定比值。允许整个人物结构与镜头调整，不能只缩放头像或贴脸；皮肤、服装、场景光源与色温一致 |
| 整体协调 | 先看整张，确认标题、人物、道具主次与留白；巨大文字、人脸和发光道具不能同时争抢前景。用户指出不协调时先重查整图比例、光影与质感，不能只把头摆正 |
| 风格一致 | 对照此前已确认的科技封面，电影感暗场景、科技轮廓光、与内容有关的主道具、粗重标题和单一亮色重点保持系列连续性，并同时通过人物衔接与整体协调；不能为修正人像退回生活写真。配色、场景和衣服按选题变化，不固定所有图必须蓝色、沙发或同一衣服 |
| 姿态与视线 | 本人默认不摆展示手势；批量图的坐站、前后倾、表情和目光按主题变化，不复用同一个人物动作 |
| 文字 | 逐行核对标题与署名；同时检查书脊、杯子、墙画、白板和卡片，没有白名单之外的可辨认文字 |
| 素材 | 产品、界面、成品细节与输入一致；无真实素材时用通用图标，没有自行加入产品Logo或把概念图伪装成真实数据 |
| 构图 | 标题不遮脸；最大道具与人物有视觉联系；装饰没有抢主视线 |
| 裁切 | 目标比例下边缘完整；需要跨比例时实际看裁切，不仅检查文件名 |
| 画幅与像素 | 仅对本次实际要求生图的画幅检查真实文件和尺寸；用户未限定时默认3:4、9:16、16:9三版。仅提示词任务不要求生成文件，单比例任务不补其它画幅；原生像素与精确导出分开记录，不把设计目标写成实际输出 |
| 同题画幅连续 | 同题已有用户明确确认的具体图时，按版本／文件／hash继续适配，锁定脸部外观、精修、发型、朝向、衣服、表情、目光、手部及身体关系，不反复换脸模型；用户未确认时沿用已自检同题图 |
| 用户反馈 | 用户否定优先于Agent目视PASS；重新记录被否定版本与实际问题。目视判断不等于精确人体测量，不用头部占高数字粉饰不协调，也不把一版认可写成三版都获用户确认 |
| 输出 | 链接指向真实文件，标明提示词、生成预览还是可用成品 |
| 来源 | 原始账号截图用于研究，新图使用用户自己的素材与品牌 |

本人封面分别检查本人身份与已确认系列外观、自然商业精修、头颈肩身体协调和科技风格。已有明确认可的系列外观时，原始照片与用户提供的多视角脸模负责真人身份辅助，不自动覆写已确认骨相、表情、精修和用光；用户明确要新外观时服从新要求。版面参考、人像基线和真人辅助需分开声明，旧版面被否定的人体比例不能继承。

没有实际出图时，只能说“提示词与构图已完成”。图片通过肉眼检查不等于经过真实平台上传，也不等于点击率效果经过验证。

## 示例 1：口播工作流

用户请求：

> $zhuzi-cover-design 给这份“用 AI 辅助整理口播稿”的视频做封面提示词，用我的照片，正文只展示整理步骤，不承诺全自动。

合适的交付：

- 标题候选：「让 AI 帮我 / 整理口播稿」「口播稿太乱 / 先做这一步」「写口播稿 / 我换了个流程」。
- 推荐第一个，A 蓝紫工作流拼贴。
- 道具：用户实际的逐字稿或段落结构截图，前景一张整理后的稿件卡片。
- 不写“自动接管整个账号”；没有素材图时用抽象段落流程，标明它是示意。
- 提供已填好的完整提示词，不再追问配色和表情；缺照片只说明出图所需素材。

## 示例 2：知识库用于真实任务

用户提供正文：过去仅收藏链接，现在把已收藏资料整理成一个能用于写稿的知识库，视频演示检索与引用。请求实际封面。

合适的交付：

- 标题：「收藏的资料 / 终于能用了」。
- B 金色结果或 A 蓝紫工作流，按现有界面素材决定。
- 道具：前景写稿成品与真实检索结果；不用钞票表达知识库的收益。
- 用已提供的本人照片实际生图，查看文字与人物后展示。
- 如果图像工具不可用，交付提示词并明确“还未生图”。

## 示例 3：判断和问句

用户正文讨论“Skill 很多，但没有实际工作流”的问题，不能证明收藏越多一定越无用。

合适的交付：

- 标题：「Skill 越多 / 越不会用？」或「收藏了 Skill / 然后呢？」。
- D 大字判断，问题词亮黄；主道具是断开的流程节点，本人侧身看向缺口，双手自然放低。
- 不把问句偷换成无证据的绝对结论。
- 请求只做一张时不生成 4 张构图，也不自动发到抖音。

## 示例 4：用户改了设计要求

用户要 9:16、浅色背景、不出镜、只给提示词。

遵从用户要求，采用样本中的浅色产品例外：真实产品或工作流成品为主，大标题加单一亮色重点。不要强制深色、本人照片或 3:4，也不为补齐默认输入连续提问。

## 示例 5：作品里的平台数字

用户指着主页截图说“封面也写 3.2 万点赞”。

先区分：该数字在截图里属于平台界面，不能误当原图文字；若用户确实想把自己的真实数据作为封面内容，确认数据来源后再排版。参考账号的成绩不能当用户成绩。

## 示例 6：线下分享合集

用户指定标题“FDE近期线下分享合集”，有一张明确认可的旧系列封面与本人照片。

- 原标题只调整分行，不擅自添加活动名称、人数、地点或数据。
- 旧系列图负责外观、精修、用光和头颈肩躯干关系，原照片只作身份辅助；不把新脸模当成必须重塑旧脸的指令。
- 没有真实活动照片时采用通用会场示意：舞台、观众席、无字抽象屏幕。避免把示意图描述成实际活动现场。
- 默认无展示手势。三画幅从同一主方案继续适配；每版检查完整标题、人物整体协调和实际像素。

## 公开版验证范围

公开包的结构、文字引用和依赖可做静态检查；这些检查不证明图像工具可用、不证明新题一定一次成功，也不证明平台点击效果。实际成图仍须逐张查看。
